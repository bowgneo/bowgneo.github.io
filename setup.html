记录这个网站的创建与发布过程，并保留使用 GitHub 网页操作的完整教程。教程可以通过鼠标和网页编辑器复现；本次实际发布使用 GitHub CLI 与 API。

网站已发布，HTTPS 已开启。正式网址：bowgneo.github.io；源码：bowgneo/bowgneo.github.io。显示名为 grant，简介与文章列表保持空白。

本地准备创建仓库上传文件发布更新与恢复

1. 本地准备与审核

网站使用 HTML 和 CSS，没有依赖安装和构建步骤。双击 index.html，用浏览器打开即可预览。

  • index.html：首页和文章目录。
  • about.html：关于页面。
  • setup.html：这份建站记录。
  • style.css：所有页面共用的样式。
  • favicon.svg：标签页图标。
  • .nojekyll：让 Pages 直接发布静态文件。

第一版做成了个人展示页。审核意见是“大标题和装饰太像 AI 模板”。第二版改为普通博客布局：白底、适合阅读的栏宽、短导航和文章目录。文章暂时留空，个人介绍不设技术方向。

10 月 26 日，显示名按本人要求修正为 grant，重新整理简介与字体层级。第三版桌面采用个人介绍与文章区分栏的布局，手机采用纵向布局，继续保留空白文章列表。

布局参考了 Julia Evans、antirez 和阮一峰的网络日志，没有复制他们的文章或个人资料。

第四版删除泛泛的写作宣言，首页与关于页暂时只保留姓名和 GitHub。页面重新收窄为单栏，参考了 Anthony Fu 与 Lee Robinson 的内容布局。

先核对名字和文字，再点击各页链接；缩窄浏览器，检查手机宽度下的排版。确认满意后，继续下面的步骤。

2. 用 GitHub 网页创建仓库

  1. 登录 GitHub，确认当前账号是 bowgneo。
  2. 点击右上角 ＋ → New repository，或打开新建仓库页面。
  3. Owner 选择 bowgneo；Repository name 填写 bowgneo.github.io。
  4. 选择 Public，打开 Add README，描述可以填“我的个人主页”。
  5. 核对仓库全名后，点击 Create repository。
  6. 进入仓库的 Code 页面，检查默认分支。本教程使用 main。

个人站点的仓库名必须是“用户名.github.io”。GitHub Free 支持公开仓库的 Pages。参见官方创建说明。

3. 用网页上传网站文件

  1. 在 Code 页面确认选择了 main，并处于仓库根目录。
  2. 点击 Add file → Upload files。
  3. 点击 choose your files，选中 index.html、about.html、setup.html、style.css 和 favicon.svg；也可以把这些文件拖进上传区。
  4. 确认五个文件直接放在根目录，不要套一层文件夹。
  5. 填写提交说明，例如 Add personal website，选择 Commit directly to the main branch，点击 Commit changes。界面如先出现弹窗，填写后再确认。

创建隐藏文件 .nojekyll

  1. 回到仓库根目录，点击 Add file → Create new file。
  2. 文件名填写 .nojekyll，保留开头的英文句点，不增加其他扩展名。
  3. 正文留空；如果编辑器不允许提交空内容，按一次回车留一行空白。
  4. 点击 Commit changes…，填写 Disable Jekyll processing，直接提交到 main。

.nojekyll 只需要存在。详细界面见官方上传文件说明。

4. 开启 Pages 并检查发布

  1. 在仓库顶部点击 Settings，再点击左侧 Pages。
  2. 在 Build and deployment 中，将 Source 设为 Deploy from a branch。
  3. Branch 选择 main，文件夹选择 /(root)，点击 Save。
  4. 打开仓库顶部 Actions，查看最新的 pages build and deployment 任务，等待绿色成功标记。红色失败时，点进失败步骤查看原因。
  5. 回到 Settings → Pages，点击 Visit site。预计地址是 https://bowgneo.github.io/，实际发布成功后才可作为本站验收地址。
  6. 检查 Enforce HTTPS。已勾选或由系统强制启用时保持即可；可以勾选时就勾选。github.io 站点支持自动 HTTPS。

/(root) 是仓库根目录，不是让你创建一个名叫 root 的文件夹。入口必须是该目录里的小写 index.html。

发布可能需要最多约十分钟。参见配置发布来源和HTTPS 说明。

5. 以后怎样更新

  1. 打开仓库 Code → main，点击要修改的文件。
  2. 点击铅笔图标 Edit this file，修改文字或链接。介绍在 about.html，首页在 index.html，外观在 style.css。
  3. 点击 Commit changes…，填写说明并提交到 main。
  4. 等待 Actions 的最新部署成功，再刷新网站。改动较多时，可以先在本地审核，再用 Upload files 上传同名文件覆盖。

GitHub 编辑器里的 Preview 不等于整页的浏览器效果。每次修改后仍要检查完整页面。编辑操作见官方说明。

改错后的恢复办法

进入文件的 History，选择确认正常的旧提交，使用 Browse files 或 View file 查看那时的文件，通过 Raw 复制完整内容。回到当前 main 的文件编辑器，替换为旧内容并提交一次新的修改。相关 HTML 和 CSS 应恢复为同一版本，再等 Pages 重新部署。

6. 常见问题

  • 404：先确认 Pages 已启用且 Actions 成功；再核对仓库名、main / (root) 和小写的 index.html。详见官方排查步骤。
  • 没有样式：确认 style.css 已上传且与 HTML 同级，文件名大小写一致。
  • 关于或建站记录打不开：确认 about.html 和 setup.html 一起上传。
  • 更新没有出现：先等部署成功，再用无痕窗口打开，排除缓存。
  • 分支不是 main：发布设置应选择实际保存网站文件的分支；本教程统一使用 main。
